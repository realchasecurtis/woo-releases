# Bounded Windows native download acceptance (not executed)

Prerequisites: independent review resolves safety gate; stable final staging executable and exact temporary ACL scope approved if required; disposable new browser profile; native Save-dialog automation/user interaction available. No setSavePath substitution. Do not activate release downloads based on mocks or this plan.

Use an owned empty temporary destination directory. Open the official Electron45.0.0 GitHub release page through the real address field/Enter. Click its small SHASUMS256.txt asset with a real trusted input gesture. Proposed public source: https://github.com/electron/electron/releases/download/v45.0.0/SHASUMS256.txt . Confirm the currently available link before running. Only save inert text; never open or execute a downloaded program. The published Woo release ZIP may be used for a promptly cancelled transfer, not installation.

1. Save-dialog cancellation: click asset, cancel native dialog, prove no completed entry and no final destination file; confirm no residual partial artifact before cleanup.
2. Completion: click again, native dialog selects a new basename under owned destination. Record actual initiating origin, frame ownership and hasUserGesture from DownloadItem; do not record query strings/cookies. Observe progress and done. Inspect resulting file as inert bytes, verify expected public checksum text shape and byte count. Read NTFS Zone.Identifier, require ZoneId=3 (or stronger Internet/Restricted zone), and check native annotation behavior on exact packaged runtime. Missing/unreadable metadata FAILS acceptance even if Chromium reports completed.
3. Native path controls: choose existing harmless fixture and Cancel overwrite confirmation; prove original bytes unchanged. Test a controlled symlink destination only if creation is supported without new privilege; otherwise mark untested, never disable protection. Test hostile filename suggestions without contacting a hostile endpoint using reviewed mock cases; actual Save path editing remains a separate native test.
4. Progress cancellation: trusted click on public release ZIP, choose owned destination, cancel from Downloads panel promptly; confirm stopped byte growth, terminal status, no auto-open. Bound run at60seconds and aggregate received bytes at32MiB; abort before exceeding test budget. Native buffers may overshoot update thresholds; record actual bytes.
5. Restart same disposable profile: history contains sanitized filenames/status/time/byte counts only; no URLs, destination paths, credentials or tokens. Clear Finished History and prove saved text file still exists unchanged. Empty state and keyboard focus/escape tested in light/dark.
6. Negative tests: no user gesture, opaque/mismatched initiating origin, foreign session/frame, file/blob/data/private destination and malicious redirects rejected. Keep native Woo content downloads blocked. Review tests can mock these; do not silently change network policy.

Marking failure is a release blocker. Native save may already have created a file before marking failure is observed; merely changing UI status to failed is NOT sufficient protection. If native behavior cannot guarantee safety, a separately reviewed staged finalization/marking design is needed before activation. No automatic deletion of user-selected existing files as remediation.

Capture app-only screenshots/receipts, retain exact process handles, close own test instances, restore scoped DACLs with zero mismatches. Remove only owned inert fixture files after recording evidence. Mac quarantine and packaged plist behavior require separate actual Mac test; Windows ADS results do not establish Mac safety.
