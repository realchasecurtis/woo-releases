# Publishing slice 0.1.1 contract — source-only

Location: task-5/publishing-slice-0.1.1. Browser 0.5.6 crypto, bundle verifier and ownership registry are copied unchanged into vendor with provenance hashes. No Browser changes.

Name: <label>.<first32OwnerFingerprint>.<last32OwnerFingerprint>.woo-test. This is a self-certifying test scope, not public domain allocation or globally exclusive friendly naming. Friendly discovery is catalogue-local.

Bundle: EXACT existing Browser {manifest:{payload,signature},files} format. Existing canonical SHA256 root, Ed25519 signatures, MIME/path policy and verifyBundle. In-memory file-map packaging replaces folder IO for this slice. Export is canonical JSON bundle bytes, not ZIP or executable. Render result supplies verified files plus Browser-compatible ownership record; future UI must use its existing sandboxed NativeRenderer.

Mapping: ordered history of existing signed Browser claim/update operations (version 1, registry woo-local-lab-v1). Client replays with unchanged OwnershipRegistry in isolated fixture mode. One explicitly documented extension: owner-signed action 'revoke' is terminal in this adapter, preserves final root/revision and increments sequence; not accepted by the old Browser registry directly. No implicit name reassignment, expiry, liveness or inactivity release. This extension requires browser adapter review before integration.

Provider seam: async list(), read(name), readBlob(root), putBlob(root, canonicalBytes), append(name, expectedHistoryDigest, operation). Append must atomically compare-and-swap and never overwrite a fork. This slice supplies bounded IN-MEMORY providers only. Catalogue supplies discovery/completeness/availability; signatures supply integrity, not proof of latest head. No GitHub or peer transport exists here.

Publisher: fixture key supplied by tests, explicit public-test-content consent, create scoped name, publish file map, revoke. Client: fresh instance, search, resolve (explicitly accept verified self-certifying scoped history), open -> record/files/bundle/exportBytes; explicit retain enables memory-only offline open. Search alone creates no trusted rollback history. Known prefix divergence/rollback fails closed; revocation is remembered when observed for an already pinned name or during explicit resolve/open, blocks normal open and clears retained copy. Downloaded copies elsewhere cannot be recalled. Fresh clients can be shown authentic stale history; full client restart loses pins/retention. Durable storage and real identities are later gates.

Limits: 32 names, 64 ordinary operations plus one terminal revoke/name, 1 MiB decoded site, 64 files, 1 MiB/file, 2 MiB encoded bundle, 8 MiB blob storage; eight retained snapshots maximum, 8 MiB retained encoded bytes. History and exports remain public synthetic material. No listeners/dependencies/credential persistence/publication. Tests use in-RAM test-only keys.

Implementation notes: known prefix forks are quarantined without deleting trusted pins; normal offline open is denied for quarantined names. In-memory catalogue writes are intended for explicitly selected test publishers, not unauthenticated internet callers. Quotas bound damage but do not establish fairness/operator independence. A hostile provider can censor or refuse content and can serve authentic old history to a fresh client. Search results are not durable admission. The terminal revoke extension is validated by this adapter only. Browser OwnershipRegistry is replayed solely for existing claim/update operations in isolated fixture mode. Full-history digest pins bind all prior operations, including timestamps and signatures.

Public exports contain bundle manifest/files only. They do not by themselves supply discovery or prove the latest ownership head; receiver also needs the verified mapping history. No private descriptor input exists; all catalogue names and uploaded bundles are explicitly public-test-content. Publisher consent does not automatically authorize real remote publication.

0.1.1 search semantics: verified revocation and fork/rollback checks apply to existing pins. A safety transition rejects the search promise with its error after updating safety state; trusted main must display it, not present an empty successful search. Ordinary unadmitted results do not create pins. An unadmitted terminal revoke is filtered but NOT remembered; a future explicit acceptance can still encounter authentic stale history. There is no silent global revocation cache.
Prefix evidence: each pin stores up to 65 prefix digests. Compare the common prefix before classifying a shorter result as rollback. Divergence at any length quarantines without deleting evidence and blocks retained open. Matching strict-prefix rollback is rejected but does not erase a labelled retained snapshot.
Capacity: verifier/provider permit operation 65 only if it is terminal revoke; no operation 66. Publisher rejects excess update before packaging or putBlob. This changes adapter history bounds only; all five SDK files remain unchanged.
